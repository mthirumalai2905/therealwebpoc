The Real-Time Web (RTW) is a new architecture for connecting, transforming, and exchanging live data across the Internet. It is written for a world in which machines, services, and people need to work with one another in the present, not only through pages that were stored yesterday.

It is designed to support machine automation and to address the <GlossaryTerm id="ioe">Internet of Everything</GlossaryTerm>: physical devices, virtual resources, software services, AI agents, sensors, actuators, and people, so they can take part in the same connected ecosystem.

The original World Wide Web was built to publish and share information: text, images, documents, and video. The Semantic Web later extended that model by making information more structured and easier for machines to read.

The Real-Time Web takes the next step. It introduces a live, bidirectional linking model that lets network resources connect directly to one another. Instead of treating data as static content retrieved from a website, RTW treats live data sources and network resources as addressable participants on the Web.

This makes it possible to connect almost any physical or virtual resource to live services through a <GlossaryTerm id="heterogeneous">heterogeneous</GlossaryTerm>, user-controlled network architecture.

This site explains that idea as a network concept and architecture. It is not a product page. The chapters below are meant to be read in order. Each one assumes the one above it.

1. **Start here.** What it is, why a new architecture is needed, how it differs from the World Wide Web, what live data is, and what that makes possible.
2. **How it works.** Live channels, the guiding principle, and how participation is structured.
3. **The architecture.** Morphic Architecture Design, the four layers, ghosts, the bijective pairing, Morphic services, data channels, and network topology.
4. **Summary.** What that path has covered so far.
